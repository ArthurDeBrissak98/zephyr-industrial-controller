# Трассируемость требований

[requirements.yaml](requirements.yaml) связывает требование, комментарий `// REQ-…` рядом с реализацией и проверку: Ztest в Twister, YAML-сценарий или UART-тест на Python. В `code` указаны файл и функция; в `verification` — существующие имена тестов. Это карта покрытия, а не отчёт об успешном выполнении: результаты запусков находятся в GitHub Actions.

`origin: acs880_analogy` означает функциональный ориентир ACS880: контроль аналогового входа, защиты, регулятор, журнал. Точная редакция мануала и номера разделов пока не установлены, поэтому `source_manual.reference_status` имеет значение `not_verified`. Поле `acs880_topic` задаёт тему для последующей сверки, а не цитату. Порог обрыва 3,6 мА, диапазоны профилей, фильтр и коэффициенты PI — требования нашего демо. Соответствие алгоритмам или безопасности ACS880 не заявляется.

`origin: project` относится к архитектуре демо: Zephyr, QEMU, мьютексы, ADC worker, watchdog, NVS и конкретная карта Modbus. Эти требования не приписываются мануалу ABB.

Проверка ссылок:

```bash
python scripts/check_traceability.py
```

Проверка находит повторяющиеся ID, отсутствующие файлы, теги, функции, Ztest и сценарии, а также теги реализации без строки в матрице. Она включена в CI и не заменяет запуск тестов. При изменении требования обновляйте реализацию, строку матрицы и соответствующую проверку вместе.

Известные границы проекта: выход на реальный привод отключён; обмен и электрические параметры на физической плате не проверены. Сборка для платы подтверждает компиляцию, а не аппаратную верификацию.
